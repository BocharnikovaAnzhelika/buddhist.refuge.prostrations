# Путь простираний

Модульная версия из двух предоставленных HTML: оформление и содержание локального прототипа, Firebase email-link + Firestore из рабочей версии.

## Файлы
- `index.html` — только разметка трёх вкладок и формы входа.
- `css/style.css` — весь дизайн, фон и прозрачность карточек.
- `assets/refuge-tree.png` — изображение Дерева прибежища, извлечённое из прототипа без изменения качества.
- `js/app.js` — счётчик, история, график, навигация.
- `js/quotes.js` — библиотека 22 поучений.
- `js/store.js` — единая модель данных, локальная копия и события изменений.
- `js/cloud.js` — Firebase Authentication, Firestore, синхронизация.
- `js/firebase-config.js` — публичные параметры Firebase.
- `firestore.rules` — правила Firestore.

## Запуск
Не открывайте `index.html` через `file://`: браузер блокирует JavaScript-модули и Firebase может не работать. Для проверки интерфейса используйте локальный HTTP-сервер: `python3 -m http.server 8000` и откройте `http://localhost:8000`. Для авторизации Firebase добавьте `localhost` в Authentication → Settings → Authorized domains, если его нет. Для реальной проверки входа проще опубликовать тестовую ветку/страницу на уже разрешённом домене GitHub Pages.

## Важно
Перед обновлением боевого сайта сохраните резервную копию данных Firestore. При первом входе можно подтвердить импорт локального прогресса. Данные локального прототипа не импортируются автоматически. Синхронизация использует транзакции и `deletedIds`, совместимые со старой версией. Одновременные правки на нескольких устройствах и офлайн-режим требуют дополнительного интеграционного тестирования. Не загружайте в репозиторий приватные Firebase service account keys.

## Прогноз завершения
Средний темп рассчитывается за последние 7 календарных дней (включая сегодня, даже если были дни без практики). Прогноз показывает срок в годах с одним десятичным знаком и ориентировочный год достижения цели. Для сроков меньше года показываются месяцы или дни. Изменения только в `js/app.js`; Firebase и структура данных не изменялись.

## Вход в веб-приложении на iPhone
После установки на экран «Домой» приложение может иметь отдельное хранилище сессии от Chrome. Поэтому уже выполненный в Chrome вход не обязательно переносится в PWA. При запуске приложение дожидается проверки Firebase Auth и явно использует `browserLocalPersistence`.

Если письмо открывается в обычном Chrome, в установленном приложении раскройте «Уже получили письмо? Вставить ссылку для входа», вставьте полную ссылку из письма и укажите тот же email. Вход завершается в контексте PWA. Ссылки одноразовые и ограничены по времени.

**Важно:** на iOS браузеры могут не позволять копировать URL из кнопки письма напрямую. Можно удержать кнопку/ссылку в письме и выбрать «Скопировать ссылку». Если почтовый клиент подменяет URL трекинговым редиректом, откройте письмо в другом клиенте и скопируйте прямую ссылку Firebase.

Тестировать авторизацию нужно на опубликованном HTTPS-домене, разрешённом в Firebase Authentication. При тестировании на GitHub Pages проверьте путь страницы в `actionCodeSettings.url`. Не меняйте правила Firestore.
